# ADR-002 — Week window and delivery date stay inside Sales and Fulfillment Output

**Status:** Proposed
**Date:** 2026-10-31
**Document role:** Architecture decision for the feature in [PDR-002](../pdrs/PDR-002.md). Binding design. Not a description of the running API.
**Depends on:** [ADR-001](./ADR-001.md). This decision does not add a deployable service or a bounded context.

## Context

PDR-002 lets the seller correct sales from any day of the current week, stores a delivery date on every sale, and builds the Load Sheet from that date. It also carries the catalog Excel import and the Alegra inbound and create/delete sync that Version 1 left unbuilt.

The risk is a new "week" or "return" aggregate that duplicates Sale, or a Load Sheet that starts writing sales.

## Decision

No new bounded context.

| Rule | Owner |
|---|---|
| Current week (Monday–Sunday of today's business date) | `sales-day`, as a date window. Not an aggregate and not a table. |
| Whether a sale may be edited or voided | `sales`, using the Sales Day date and that window. `CLOSED` is not the lock inside the week. |
| Delivery date | A required value on the `Sale` aggregate. |
| Load Sheet rows for one delivery date | `fulfillment-output`, read-only, grouped by `productId`. |
| A return | The existing edit and void use cases. No return aggregate, no negative line. |
| Excel import, Alegra inbound, create/delete sync | `catalog` and the existing `alegra` outbound port. |

Cross-context reads stay in `src/apps/dependency-injection/acl/`. Fulfillment Output still does not write a Sale. The week window uses the business timezone already configured for Sales Day. It does not use the browser clock.

## Rejected alternatives

### A Sales Week aggregate

Rejected. The week is a calendar window over Sales Days that already exist. A stored week would add a lifecycle the business did not ask for.

### A Return document

Rejected. The seller changes the sale or voids it. A second document would allocate numbers and split the Load Sheet source.

### Keeping the Load Sheet keyed by Sales Day

Rejected. PDR-002 states that the load follows the delivery day. Sales captured on Monday for Wednesday belong on Wednesday's sheet.

### A rolling 7-day list

Rejected. That is the current hub. It shows days from the previous week. The hub is the current week only.

## Consequences

`ListRecentSalesDays` is replaced by a current-week query. Sale commands grow a delivery date and a week guard. `GenerateLoadSheet` takes a delivery date. Invoice numbering and the Sale status machine stay. Catalog migration and Alegra sync do not pass through Sales.
