# PDR-003 — Product administration and Alegra

**Status:** Proposal
**Language:** English
**Scope:** Next catalog feature. Independent of delivery days.
**Document role:** Product design requirement. Business source of truth for this feature. Not a description of the running API.
**Takes from PDR-002:** the catalog backlog that was attached to delivery days (Excel import, Alegra inbound pull, and Alegra sync on create and delete). Update sync already exists in the running API and stays.

## 1. Purpose

The seller administers the product catalog from the client: create a product, update it, and retire it. The local catalog and Alegra stay aligned. Alegra is not called from the browser.

## 2. What the seller can do

1. Open **Productos** from the home screen. The entry does not depend on a delivery date.
2. Create a product. The API stores it. The reference Alegra script has no create request, so creation does not call Alegra yet.
3. Update the fields the screen can edit. Every one of them is stored, including `0`. An empty value is rejected. Alegra is told only the name and the wholesale and retail sale prices that were sent, including a sale price of `0`. Cost, units, and pack are not sent to Alegra.
4. Retire a product with a logical delete. The product remains stored and leaves sale search. The reference script has no retire request, so retiring does not call Alegra yet.

## 3. Rules

- A product that is already on a sale stays on that sale after it is retired. Past invoices keep their snapshots.
- Excel import is a one-shot load of the current workbook. Invalid and duplicate rows are reported. Values are not silently dropped or rewritten.
- Listing or pulling items from Alegra is out of scope.
- An Alegra failure after a successful local save is logged and does not undo the local save.

## 4. Out of scope

- Delivery dates, Load Sheet, invoices, and sale correction. Those stay in [PDR-002](./PDR-002.md).
- Inventory quantities.
- Calling Alegra from the UI.

## 5. Acceptance criteria

- Productos is reachable without choosing a delivery day.
- Creating a product persists it and does not call Alegra.
- Every edited field is stored, including `0`. An empty update value is rejected. Alegra receives only a changed name and the changed wholesale and retail sale prices, including `0`. Cost, units, and pack stay local. Omitted fields stay as stored. Negative numbers are rejected.
- Retiring a product hides it from sale search, keeps it in storage, and does not call Alegra.
- An Alegra failure does not roll back the local change.
- Excel import reports invalid and duplicate rows.
